## 阶段一 · 方法论设计

起点是一个设想：找一个成熟、常用于技术学习的项目，由教学 AI 拆解出模块与核心算法；然后把项目重排成一串逐步交付的需求，让学生先自己写 MVP（技术栈、算法全部自主选择），再由教学 AI 把学生作品与项目对照、记录优缺点；一轮轮推进，直到完整重建整个系统。

这个初始设想在落地前经过四轮关键取舍，最终结论沉淀在阶段二的 `00_方法论设计.md` 里：

1. **对照策略**：自主选型会让技术栈与基准不一致，而"对照原项目"需要可比性。曾权衡的选项之一是"指定技术栈换取可比性"，最终选择折中方案——架构层自由对照（比设计决策），关键算法用固定场景定点比拼（比实现细节）。
2. **迭代驱动方式**：初始设想是"告诉学生系统有哪些缺陷"。改为增量需求驱动，理由是缺陷驱动暗含"AI 心里有标准答案"，会把自主产出退化成猜答案。这一修正被明确记录在 `00_方法论设计.md` 的"设计修正记录"中。
3. **角色架构**：定为双 AI——指导老师持有教案，协作助手不知道答案。信息隔离是前提，否则对照退化为抄作业。
4. **完成标准**：定义为达成教学目标，而不是复现基准的全部功能。

同批修正还包括：对照后增加反思环节、增加理解验证与"对 AI 输出保持批判"的要求。

**遗留**：这轮设计的讨论过程没有归档，只有结论。当时权衡过哪些具体备选方案、被否的理由是什么，缺乏一手记录。

## 阶段二 · RAG 试点（2026-09-08 15:22–15:24）

方法论需要在一个真实场景上先验证，选定的基准项目是 `production-rag-pipeline`——一个覆盖"切分 → 向量化 → 检索 → 混合检索 → 重排 → 生成 → 评估"全链路的 RAG 管线。

产出一套完整资料包 `RAG学习/AI学习法资料包/`：

- `00_方法论设计.md`：方法论原理、四个支柱、双 AI 架构、每轮闭环
- `01_原项目拆解报告.md`：基准项目的模块地图、核心算法、架构决策点、教学化裁剪
- `02_增量需求与交付路线.md`：六轮增量，每轮含需求、自主决策点、对照模块、教学点、交付价值、验收标准
- `03_对照记录模板.md`、`04_golden_set与评估方案.md`、`打卡表.md`
- `skills/`：两个专用角色 skill（`rag-learning-instructor`、`rag-learning-assistant`）

这一阶段的几个设计决定影响了后续所有版本：双角色 skill 做成两个独立可安装的文件；增量数据源按"先小后大"扩展；学生守则里写明"对照前不翻阅基准实现"。

**遗留**：试点实际推进到第几轮、每轮对照结论如何，需查 `打卡表.md` 与对照记录文件确认，本文件不臆断。

## 阶段三 · 通用化：v0.1.0（2026-09-08，提交 `5298a7d`）

RAG 资料包完成后，紧接着的目标是把这套方法从"某个项目的专用流程"变成"指定任意项目都能跑"的通用 skill，并开源到 GitHub。

关键决策：

1. **命名与仓库**：skill 名 `ai-project-learning`，仓库 `ai-project-learning-skill`。
2. **运作模式定两种**：单 AI 全流程（默认，一个 AI 分阶段切换指导与协作角色）与双 AI 严格信息隔离（用 `roles/` 下两个独立 skill 分别装入两个窗口）。
3. **目录结构**：主 `SKILL.md` 保持精简，方法论下沉到 `references/` 按需读取；角色 skill 独立放在 `roles/`，可单独安装。
4. **泛化方式**：把 RAG 专用角色 skill 里的项目特定内容剥离，角色职责、守则与红线保留为通用条款。

产物为 11 个文件（主 skill、5 份 references、2 个角色 skill、README、LICENSE、.gitignore），首次提交 `5298a7d`。仓库推送由作者手动完成。

## 阶段四 · 交流规范：v0.2.0（2026-09-08，提交 `e751af0`）

作者在试用中暴露两个问题：一是教学 AI 在决策提问里使用专业名词，初学者被术语挡住无法决策；二是 AI 会给出倾向性推荐，学生容易"跟着推荐走"，自主决策形同虚设。

由此确立四条规则，写入新增的 `references/communication-guide.md`：

1. **术语脚手架**：关键概念首次出现时附一行"它在本项目里管什么"，不展开长文；并明确判断标准——解释通用概念不算泄露答案。
2. **提问邀请**：每轮开场明示可随时打断提问，兜住初学者"不知道自己不知道"的情况。
3. **禁止倾向性推荐**：列出禁用词，规定被反问"你推荐哪个"时不给倾向答案，改用提问反推学生的约束条件。
4. **项目学习笔记**：这条的定位经过一次调整——最初设想是"学习笔记由学生自己写，兼顾元认知"，后改为由 AI 代写。理由是学习已经发生在"询问 → 思考 → 决策"的过程中，笔记只需承担留档回看职责，而"是否真的学会"由理解验证环节负责。这一分工沿用至今。

同时修复了一处规则冲突：协作助手 skill 中写着"可以推荐，但不替他拍板"，与禁止倾向性推荐的规则直接矛盾，改为禁止推荐。

**同期产物**：一篇面向微信公众号的推广文章（属对外材料，未纳入仓库）。

**遗留**：本阶段没有独立的升级记录文档，其起因与决策只在本文件与 `CHANGELOG.md` 中留存。

## 阶段五 · 规范化升级：v0.3.0（2026-09-14，提交 `340a9b3`）

触发点是一次规范审查：调研 Agent Skills 的官方编写规范与社区实战经验，对照检查现有 skill 的结构合规性。

调研采信的结论包括：SKILL.md 应控制在 500 行内、引用保持一层深且需写明触发场景、红线前置并正向表达、否定指令堆砌存在反作用、只用 `name` + `description` 时跨客户端可移植性最好、skill 应配触发与行为评估。

据此完成 11 项优化，分三档：

- **P0**：references 引用改为显式读取指令；统一"对照开始前后能否接触基准源码"的口径（此前指导老师 skill 与对照协议表述冲突）；原"红线"章节前置为执行纪律表并改为正向表述；README 增加规则三处同步的维护约定。
- **P1**：合并主 skill 内部重复表述；frontmatter 补 `license` 与 `metadata`（author、version）；新增 `references/example-walkthrough.md` 演示一轮完整迭代。
- **P2**：新增 `evals/`（20 条触发查询 + 3 个行为用例）；命令接口补跨客户端等价说法；README 增"面向初学者的四个机制"；新增 `CHANGELOG.md` 与版本字段。

**遗留**：触发评估与行为评估尚未实跑，`evals/` 中的目标是设定值而非实测结果；尚无第三方使用反馈；`name` 采用名词短语而非官方推荐的动名词形式，因已开源发布、更名有成本，暂不调整。

## 阶段六 · 决策中立化：v0.4.0（2026-09-14）

起因是一个复发问题：v0.2 已经立下"禁止倾向性推荐"的规则，但实践中 AI 在提供可用方案时仍带有推荐。根因不在用词，而在规则结构——旧规则禁止"推荐"字样，同时允许"给出选项与各自权衡"，而权衡本身就构成评价："X 更轻量""X 适合快速验证"这类描述即使不含"推荐"二字，框架已经倾斜，选择随之被引导。

本轮把"评价出现的时机"引入规则：

- **决策前**：只做对称的中性枚举。每个选项给"它是什么"的事实属性——依赖、运行环境要求、涉及组件、许可，所有选项用同一组维度、长度相当；评价性形容词与适用性判断一律不出现。
- **决策后**：先请学习者讲自己的理由与预期代价，再由 AI 说明他选的这条路的利弊、相对其他选项放弃了什么。措辞针对所选方案，不用"我本来推荐…"评判选择。
- **被追问时**：把约束条件反推给学习者；即使他说"你替我定"，也只补中性事实，不替他选。

这次升级同步做了一次一致性审计：旧规则的影响面不止一处，示例文档、README、评估用例中都有与之冲突的表述（示例里的选项描述带评价、只给单侧缺点），一并修正，避免"课本与老师打架"。

决策后"先请学习者讲理由"这一步是在实现中补上的——如果 AI 先说利弊，学习者就只剩复述，理解验证会失去意义。这个顺序保证利弊分析仍然是学习者思考的补充，而不是替代。

**残留风险**：中性枚举的信息量低于带评价的权衡，初学者可能更难决策。规则允许给事实属性来缓解，但效果需要在实际使用中观察。



## 关键决策一览

| 决策点 | 曾权衡 | 最终选择 | 主要理由 |
|---|---|---|---|
| 对照策略 | 指定统一技术栈 / 自由选型 | 混合对照：架构层自由、实现层定点 | 兼顾自主选型与可比性 |
| 迭代驱动 | 缺陷驱动 / 增量需求驱动 | 增量需求驱动 | 缺陷驱动会暗示存在标准答案 |
| 角色架构 | 单 AI / 双 AI | 双 AI 信息隔离，另提供单 AI 模式 | 结构上保证先产出后对照 |
| 完成标准 | 复现基准 / 达成教学目标 | 达成教学目标 | 学习目标是能力而非克隆 |
| 笔记作者 | 学生自写 / AI 代写 | AI 代写，学生回看 | 学习发生在决策过程，笔记只负责留档 |
| 结构组织 | 单文件 / 主 skill + references | 分层，方法论下沉 | 控制上下文占用，按需加载 |
| 评价的时机 | 决策前给权衡 / 移到决策之后 | 决策后给利弊说明 | 权衡本身带立场，决策前给会引导选择 |
