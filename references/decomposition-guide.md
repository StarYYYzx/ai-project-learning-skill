# 拆解方法（Decomposition Guide）

把任意有现成代码的项目拆成可教学的教案。目标是产出：软件工程分析、模块结构、核心算法、架构决策点、里程碑草案。

## 第一步：软件工程分析（开工前先做）

在拆模块之前，先从软件工程视角把项目读明白。分析要**覆盖学习范围内的全部代码**，但不必逐行通读。

1. **可运行性验证**：按 README 安装依赖、跑测试、跑示例。跑不起来就先解决环境问题——基准跑不起来，后续对照全部不可信。把可用的命令记下来。
2. **模块地图**：按"职责边界清晰"划分，不按文件数量。每个模块记：一句话职责、对外接口、依赖关系。
3. **依赖与数据流**：画出模块间调用关系与数据流向；标出入口、核心、外围。
4. **质量属性**：项目在性能、可扩展性、可维护性、部署方式上的取舍，以及这些取舍落在哪些模块。
5. **架构决策**：列出关键取舍——为什么这样分层、为什么用这个模式、配置怎么驱动。每条记"决策 / 备选 / 理由 / 代价"，这就是后续对照的参考答案库。
6. **可教学点清单**：标出哪些模块适合作为学习对象、哪些只作背景。

**边界**：大型项目只分析与学习范围相关的模块；通读全仓不是学习，是代码审计。

## 第二步：拆到可教学的粒度

拆解粒度只到三层：模块职责、核心算法、架构决策点。不深入函数级——函数级细节留给对照环节按需查看。

1. **核心算法盘点**：找出值得学的算法/策略（检索融合、调度策略、缓存设计、状态机等），标注教学价值与难度。
2. **架构决策点提取**：从上面的软件工程分析里挑出适合让学生重新决策的点，每个点写清约束与代价。
3. **教学化裁剪**：标注值得学 / 可略过。裁剪对象：仅为历史兼容存在的复杂度、CI 与部署细节、与学习目标无关的外围功能。

## 第三步：任务级滚动拆分

**不要**在这一步把整个项目拆到小步骤。只拆：

- 当前里程碑的小步骤（1-2 个决策点、单一可验证交付）
- 下 1-2 个里程碑的粗略形态

其余里程碑只保留"目标能力 + 验收 + 涉及模块"，等学到时再展开。拆分规则见 `increment-design.md`。

## 拆解产物格式

写入 `lesson/analysis.md`：

```
# 软件工程分析：<项目名>

## 项目定位（一句话 + 为什么适合当学习基准）

## 可运行性验证（安装 / 运行 / 测试命令，实测结果）

## 模块地图（目录树 + 每个模块一行职责）

## 依赖与数据流

## 质量属性与架构决策（决策 | 备选 | 理由 | 代价 | 对照价值）

## 核心算法清单（算法名 | 教学价值 | 学习难度）

## 可教学点与裁剪（值得学 / 可略过）

## 学习范围（全项目 / 指定模块切片，及理由）
```

里程碑草案写入 `lesson/roadmap.md`，格式见 `increment-design.md`。

## 基准项目筛选标准

给用户推荐项目时按此筛选：

- 有现成代码、完整可运行、文档可读
- 模块边界清晰，有 1-3 个可深挖的核心算法
- 能拆出 2 个以上可演示的里程碑
- 规模与学习范围可控：太大时允许只取一个模块切片，不要求覆盖全项目

规模本身不再是排除条件——大型项目用"学习范围切片 + 滚动拆分"处理，而不是硬压成几轮。
