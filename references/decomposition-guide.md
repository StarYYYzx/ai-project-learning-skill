# 拆解方法（Decomposition Guide）

把任意基准项目拆成可教学的教案。目标是产出三样东西：模块结构、核心算法、架构决策点。

## 拆解步骤

1. **通读定位**：读项目 README 与目录结构，画出顶层模块地图，标出入口、核心、外围。
2. **模块拆解**：逐个模块记录——职责（一句话）、对外接口、依赖关系。模块的划分标准是"职责边界清晰"，不是文件数量。
3. **核心算法盘点**：找出项目中值得学的算法/策略（如检索融合、调度策略、缓存设计、状态机），标注每个算法的教学价值。
4. **架构决策点提取**：列出设计上的关键取舍——为什么这样分层、为什么用这个模式、配置怎么驱动。这些是架构层对照的维度。
5. **教学化裁剪**：标注哪些部分值得学、哪些略过。裁剪对象：仅为历史兼容存在的复杂度、环境性问题（CI、部署细节）、与学习目标无关的外围功能。

## 拆解产物格式

```
# 项目拆解：<项目名>

## 项目定位（一句话 + 为什么适合当学习基准）

## 模块地图（目录树 + 每个模块一行职责）

## 核心算法清单（算法名 | 教学价值 | 学习难度）

## 架构决策点（决策 | 取舍 | 对照价值）

## 教学化裁剪（值得学 / 可略过）
```

## 基准项目推荐标准

给用户推荐项目时按此筛选：完整可运行、文档可读、模块边界清晰、有 1-3 个可深挖的核心算法、需求可以拆成 4-8 个有独立价值的增量。规模太小没有拆解空间，太大（大型框架）拆解与对照成本失控。
