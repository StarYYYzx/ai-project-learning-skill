# 偏离控制（Drift Control）

学习者自主设计，必然出现与基准不同的路线。**不同不等于偏离**：设计层可以完全不同，只要能力层守得住。本文件定义什么时候算偏离、怎么处理、以及原系统没有的新决策点怎么写进档案。

## 1. 偏离的判据

不是"和原项目不一样"，而是以下任意一条成立：

- 当前里程碑的能力基线（黑盒用例）无法通过，且不是暂时未实现
- 后续里程碑在当前设计下不可达，或需要推倒重来
- 评测出现回归，且不是本轮预期内的波动
- 范围爆炸：为保住能力所需工作量明显超出该里程碑的既定预算

设计风格、模块划分、技术栈不同，都不算偏离。

## 2. 三级偏离与处理

| 级别 | 表现 | 处理 |
|---|---|---|
| 局部偏移 | 只影响本步骤实现，能力基线不受影响 | 记录进 `notes/step-XX-review.md`，继续推进 |
| 结构偏移 | 影响当前或后续里程碑的可达性 | 进入偏离评审，用户决定是否调整 |
| 目标偏移 | 用户实际上想做一个不同的系统 | 进入偏离评审；确认后建分支，重设基线 |

### 偏离评审流程

1. **指出事实**：受影响的能力、要返工的范围、失效的后续步骤、预计增加的工作量。只给事实，不给"应该选哪个"。
2. **用户选择**：
   - 调整设计，保住原能力基线
   - 裁剪范围，明确放弃哪些能力（记入 `notes/parity.md` 的"范围裁剪"）
   - 分叉目标，按新目标重设路线
3. **更新档案**：`lesson/roadmap.md`、`PROGRESS.md`、`notes/parity.md`、`notes/evals.md` 同步修改，写清变更原因。
4. **记录**：写进当前里程碑档案的"偏离记录"一节，注明级别、判据、用户选择与影响。

评审期间仍遵守决策中立：AI 不替用户选，不暗示某条路更省事。

## 3. 目标偏移：分支与重设基线

用户选择分叉目标时：

- 按 `references/git-workflow.md` 建 `goal/<slug>` 分支。
- 新基线 = 用户确认的新规格，不再以原项目的能力为准；原项目只作参考实现。
- `notes/parity.md` 改为"新目标 vs 当前实现"，原项目的差异另起一节"与原项目的差异（参考）"。
- 原学习路径保留在主分支，不删除、不改写历史。

这是合理的分叉，不是失败。方法的目标是学会设计与判断，不是强制复刻某个项目。

## 4. 无基准决策

原系统没有的决策点，按以下方式处理：

- **标记**：在决策记录里写"无基准决策"，不假装存在标准答案。
- **仍然中立**：照常列约束、事实属性与可选方向，由用户决定；不因为"没有对照"就替他选。
- **判断依据**：记录用户的选择依据——项目已有约束、通用工程原则、类似系统的做法（作为参考，不作为标准）。
- **对照表**：里程碑表增加一列"对照状态"，取值 `有基准` / `无基准`。无基准的行，"原项目选择"填"无"，"教学点"写判断依据与代价。
- **影响检查**：新决策点如果改变能力范围，转入偏离评审。

## 5. 常见错误

- 把"和原项目不同"当偏离，逼用户改回基准做法。
- 把"能力缺失"当设计自由，不记录范围裁剪。
- 目标已经变了，还在用原项目的验收标准打分。
- 新决策点硬套原项目，编造一个"标准做法"。
