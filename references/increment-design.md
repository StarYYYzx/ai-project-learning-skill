# 增量设计（Increment Design）

把拆解产物（结构视图）重编排为需求增量序列（价值视图）。核心提醒：**模块拆解 ≠ 交付增量**——真实产品的增量按用户价值排序，一个增量常横跨多个模块。

## 增量设计步骤

1. **按价值排序**：想清楚"一个可用的系统从小到大怎么长出来"，排一个最小可用版本（MVP）在前，其余增量按"每加一块，系统价值明显变大"排序。
2. **为每个增量配齐六要素**：
   - 需求：用户视角的描述（做什么、解决什么）
   - 自主决策点：这一轮让用户自己选什么（技术栈、算法、数据结构）
   - 对照模块：这一轮对照基准的哪些模块
   - 教学点：这一轮学到的核心知识
   - 交付价值：这一轮完成后系统比上一轮强在哪
   - 验收标准：可验证的完成条件（不要"运行良好"这种空话，要"对 X 场景的 Y 查询返回带来源的回答"）
3. **粒度选择**：默认 4-8 轮。粗粒度（3-4 轮）周期短，细粒度（6-8 轮）每轮一个清晰教学点、对照次数多、学习收益大。与用户确认粒度偏好。
4. **数据源/素材渐进扩展**（适用于内容型项目）：首轮只处理最小数据子集，后续每轮扩展，便于调试也便于做评测集。

## 增量路线图格式

```
| 增量 | 需求（新增） | 自主决策点 | 对照模块 | 教学点 | 交付价值 | 验收标准 |
```

## 常见错误

- 按模块顺序当增量（把"结构视图"当"交付顺序"）——应按价值排序。
- 一轮塞多个教学点——每轮聚焦一个，对照才有深度。
- 验收标准不可验证——每条标准都要能"跑一下就知道过没过"。
