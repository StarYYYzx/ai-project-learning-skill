# 里程碑与步骤设计（Increment Design）

把拆解产物（结构视图）重排成学习与开发的路线（价值视图）。核心提醒：**模块拆解 ≠ 交付顺序**——真实产品按用户价值生长，一个可演示能力常横跨多个模块。

## 三层结构

| 层级 | 定义 | 判定标准 | 数量 |
|---|---|---|---|
| 项目 | 学习对象 | 有现成代码、可运行 | 1 |
| 里程碑 | 一个可演示的价值单元 | 结束时能做一次演示，能力明显强于上一阶段 | 由项目规模与价值单元推导，**不设固定上限** |
| 小步骤 | 单一可验证交付 | 一次会话内能完成；结束能跑、能验；内部 1-2 个设计决策 | 由里程碑验收标准拆出，**不预设总数** |

数量级参考（是示例，不是配额）：

- 小型命令行工具：2-3 个里程碑，6-12 个小步骤
- 中型服务：4-6 个里程碑，20-40 个小步骤
- 大型框架：6-10 个里程碑，40 个以上小步骤；先选学习范围切片可显著减少

**不要用固定数字（如 4-8）套所有项目。** 轮数由规模、价值单元与学习范围推导；强行压缩会把教学点挤在一起，对照失去深度。

## 里程碑设计

1. **按价值排序**：先排最小可用版本（MVP），之后每个里程碑加一块"用户能看见的能力"。
2. **每个里程碑配齐**：
   - 目标能力：完成后系统能做什么
   - 演示脚本：怎么演示、演示什么
   - 验收标准：可勾选的完成条件
   - 能力基线：从基准抽取的黑盒用例编号，里程碑验收必须全过
   - 涉及模块：这一阶段会碰到的基准模块
   - 对照范围：里程碑末对照表覆盖哪些决策点
   - 教学主题：这一阶段的核心知识
   - 预估步数：区间，不是定数
   - Git 标签：里程碑完成时打的标签名（如 `M2`）
3. **里程碑是揭示节点**：结束时做一次完整对照表与反思，学生此后可自行翻阅基准源码。

## 小步骤设计

每个小步骤配齐六要素：

- 需求：用户视角描述（做什么、解决什么）
- 自主决策点：本步让用户拍板的设计选择，控制在 1-2 个
- 对照模块：本步对照基准的哪些部分
- 教学点：一个，聚焦才讲得深
- 交付价值：本步完成后系统比上一步强在哪
- 验收标准：可验证，跑一下就知道过没过；另加评测样例

### 小步骤完成标准（DoD）

- **能跑**：有可执行入口或命令
- **能验**：验收标准逐条可勾选
- **能讲**：用户能讲清本步的 1-2 个设计决策，并指出 AI 实现中一处他认为可疑或可改的地方
- **有档**：`notes/step-XX.md` 已写，`PROGRESS.md` 已更新
- **有提交**：按 `references/git-workflow.md` 完成一次步骤提交，提交信息与本步交付一致

五条缺一不可，不用"基本完成"放过。

## 滚动规划（大型项目必用）

- 阶段 1 只做两件事：**里程碑级全量粗描** + **当前里程碑的步骤细拆**（可多看下 1-2 个里程碑的粗略形态）。
- 每个里程碑结束时，再展开下一个里程碑的小步骤。
- 不一次性把整个项目拆到任务级：大型项目成本高，早期判断会被后续推翻，而且学生还没学到那一步。

## 与敏捷开发的对应

| 敏捷概念 | 本方法 |
|---|---|
| Backlog | 里程碑下的步骤列表 |
| Iteration / Sprint | 一个小步骤（以可验证交付为边界，不按固定时长） |
| Definition of Done | 验收标准 + 上面四条 DoD |
| Iteration Review | 里程碑演示 + 完整对照表 |
| Retrospective | 用户自己写的反思 |

借的是骨架，不引入固定 sprint 周期与故事点估算——学习项目的产出是不可预测的，按交付切分比按时间切分更稳。

## 路线图格式

里程碑级：

```
| 里程碑 | 目标能力 | 演示脚本 | 验收标准 | 能力基线 | 涉及模块 | 对照范围 | 教学主题 | 预估步数 | Git 标签 |
```

步骤级（只展开当前里程碑）：

```
| 步骤 | 需求（新增） | 决策点 | 对照模块 | 教学点 | 交付价值 | 验收标准 | Git 提交 |
```

## 常见错误

- **用固定数字套项目**：4-8 轮是小项目经验，不是通用规则。
- **按模块顺序当交付顺序**：把"结构视图"当成"用户价值顺序"。
- **一步塞多个教学点**：每步聚焦一个，对照才有深度。
- **验收标准不可验证**："运行良好""体验流畅"这类写法无效。
- **一次性拆到任务级**：大型项目会拆出大量很快过时的任务。
- **把"能跑"当成"学会"**：DoD 里"能讲"和"能跑"同等重要。
- **一次提交混多个步骤**：提交与步骤一一对应，否则回滚与对照都会失真。
